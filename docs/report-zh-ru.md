# / Отчёт об ошибке

## Иконки зданий в меню строительства пустые / 建造菜单建筑图标空白

**Статус:** воспроизведено и исправлено на стороне мода (Harmony), APK не изменялся / 已复现并在模组层（Harmony）修复，未修改 APK
**Затронуто / 影响版本:** `com.ports1de.waylith` 0.0.22 (UI 0.0.22), RimWorld 1.7.4990 rev1069, Waylith engine
**Область / 影响范围:** **только часть устройств** — на большинстве устройств проблема не наблюдается / **仅部分设备出现** —— 多数设备无此问题
**Дата / 日期:** 2026-11-14

---

## 1. Краткое описание / 摘要

**RU.** В меню строительства (Architect) у части построек вместо иконки остаётся пустая рамка с фоном. Иногда на один кадр появляется обрезанный/неполный фрагмент текстуры и снова исчезает. Сама постройка при этом корректно отображается на карте. В логах и logcat нет ни ошибок, ни предупреждений, ни падений. Воспроизводится как на новом поселении, так и на сохранении; у пострадавших устройств — стабильно, начиная с первого запуска игры.

**ZH.** 在建造菜单（Architect）中，一部分可建造物的图标只剩一个带底色的空框，偶尔闪出一帧不完整的贴图后又消失。该建筑本身在地图上显示正常。日志与 logcat 中没有任何错误、警告或崩溃。新开图和读档都能复现；出现该问题的设备上，从第一次启动游戏起就是稳定复现。

## 3. Симптомы / 症状

**RU.**
1. В меню строительства у части объектов (кровати, в т.ч. `RoyalBed`; `NutrientPasteDispenser`; ряд столов) вместо иконки — пустая рамка с фоном плитки.
2. Периодически на 1–2 кадра появляется неполный фрагмент текстуры (полоса/угол), затем снова пусто — «мерцание».
3. Постройки без `uiIconMaterial` (`Wall`, `MealNutrientPaste`, `DiningChair`) отображаются нормально — то есть проблема затрагивает не все иконки, а подмножество.
4. Сама постройка на карте рисуется корректно.
5. Никаких сообщений об ошибке, ни диалогов, ни записей в логах.

**ZH.**
1. 建造菜单里部分物件（各种床，含 `RoyalBed` 豪华双人床；`NutrientPasteDispenser` 营养膏制造机；部分桌子）的图标只剩一个带底色的空框。
2. 每隔一段时间会闪出 1–2 帧不完整的贴图（一条边或一个角），随即又变空 —— 即“闪烁”。
3. 没有 `uiIconMaterial` 的物件（`Wall` 墙、`MealNutrientPaste` 营养膏、`DiningChair` 餐椅）显示正常，说明受影响的是**一部分**图标而非全部。
4. 同一建筑在地图上渲染完全正常。
5. 全程无报错、无弹窗、无日志。

## 4. Причина / 根因（код порта / 移植层代码）

**RU.** Иконка рисуется только при наличии материала, и этот путь «молча» отбрасывает всю плитку.

**ZH.** 图标带材质时走的是材质绘制路径，而这条路径会“静默”丢弃整块绘制。

### 4.1 Поля иконки заполняются один раз и могут остаться пустыми / 图标字段只填一次，且可能是空值

`Verse/BuildableDef.cs:304-334`

```csharp
uiIconMaterial = MaterialPool.MatFrom(request);   // вариант CutoutComplexUI
uiIcon = (Texture2D)val.mainTexture;              // :333
```

**RU.** В этом порте `Material.mainTexture` всегда возвращает `null` (строки `mainTexture` нет в `Waylith.dll`, `PortUI.dll`, `Waylith.UnityCompat.dll`; единственное вхождение — в `Assembly-CSharp.dll`). Поэтому `uiIcon` может остаться пустым, хотя `uiIconMaterial` создан.

**ZH.** 该移植层里 `Material.mainTexture` 恒为 null（`Waylith.dll`、`PortUI.dll`、`Waylith.UnityCompat.dll` 中 `mainTexture` 字符串出现 0 次，仅 `Assembly-CSharp.dll` 出现 1 次）。因此 `uiIcon` 可能为空，而 `uiIconMaterial` 却已创建。

### 4.2 Шейдер иконки отбрасывает плитку при нестандартном `_MainTex_ST` / 着色器在非缺省 `_MainTex_ST` 时整块丢弃

`Data/Core/Shaders/Map/CutoutComplex.frag.glsl`

```glsl
vec2 uv = vUv * uMaterial._MainTex_ST.zw + uMaterial._MainTex_ST.xy;  // zw = масштаб, xy = смещение
...
if (f.a < 0.5) discard;
```

**RU.** Порядок компонентов здесь обратный юнитивскому `(scale.xy, offset.zw)`. При любом нестандартном значении `_MainTex_ST` (или при пустой/прозрачной `_MainTex`) `uv` вырождается в константу, сэмпл попадает в прозрачный угол, и весь квад отбрасывается по `discard`. Ни исключения, ни сообщения — просто ничего не рисуется.

**ZH.** 这里的分量顺序与 Unity 约定的 `(scale.xy, offset.zw)` 相反。只要 `_MainTex_ST` 不是缺省值（或 `_MainTex` 为空/透明），`uv` 就退化成一个常量，采样落在透明角上，整个四边形被 `discard` 丢弃。既不抛异常也不打日志，就是什么都不画。

### 4.3 Дополнительная «тихая» точка выхода / 另一个静默出口

`ImGuiGuiBackend.DrawTextureWithMaterial()`:

```csharp
if (!frameActive || !drawingEnabled || image == null || material == null
    || passMaterial == null || DrawsNothing(rect)) return;
```

**RU.** При `passMaterial == null` или вырожденном `rect` метод выходит без отрисовки и без диагностики.

**ZH.** 当 `passMaterial == null` 或 `rect` 退化时，该方法直接返回，既不绘制也不留任何诊断信息。

## 5. Доказательства (CI, без устройства) / 证据（在 CI 上，不依赖手机）

**RU.** Собран офскрин-рендерер на C (Vulkan, программный lavapipe), который запускает **настоящий** фрагментный шейдер с **настоящими** текстурами, извлечёнными из `assets` APK.

**ZH.** 用 C 写了一个离屏渲染器（Vulkan，软件实现 lavapipe），运行**真实**片元着色器与从 APK `assets` 提取的**真实**贴图。

| Вход / 输入 | Результат / 结果 |
|---|---|
| `_MainTex_ST = (0,0,1,1)`, текстура `RoyalBed_south` | `15660 / 16384` = **95.58 %** (= доля непрозрачных пикселей текстуры / 等于贴图不透明率) |
| `_MainTex_ST = (1,1,0,0)` (юнитивский порядок / Unity 顺序) | **0 / 16384** |
| `_MainTex` полностью прозрачная / 主贴图全透明 | **0 / 16384** (проверка привязки / 绑定自检) |
| `NutrientDispenser_north` 192×256 | `45410 / 49152` = **92.39 %** |

**RU.** Таким образом, «вырожденный uv ⇒ плитка исчезает полностью» воспроизведено на реальном шейдере; совпадение процентов с плотностью текстуры подтверждает корректность теста.

**ZH.** 也就是“uv 退化 ⇒ 整块消失”已在真实着色器上复现；像素比例与贴图不透明率逐位吻合，说明测试本身可信。

## 6. Исправление / 修复

**RU.** Мод Harmony (`agenttouchfix`, версия `v40-drawfix` 2.3.0), APK не трогаем, ничего не пересобираем и не переподписываем. Патч ставится на `Verse.Widgets.ThingIcon(Rect, ThingDef, …)` и в момент отрисовки:

1. если `uiIcon` пуст или `BaseContent.BadTex` — подгружает реальную текстуру по `graphic.path` (fallback: `graphicData.texPath`, затем `+ "_south"`) через `ContentFinder<Texture2D>.Get(path, false)` и записывает в `def.uiIcon`;
2. если `uiIconMaterial` начинается с `CutoutComplexUI` — обнуляет его, и иконка уходит на обычный путь `DrawTextureWithTexCoords()` — тот же, что используют корректно отображающиеся иконки (`Wall`, еда).

Обе операции идемпотентны: при здоровых полях не делают ничего.

**ZH.** 采用 Harmony 模组（`agenttouchfix`，版本 `v40-drawfix` 2.3.0），不修改 APK、不重打包、不重签名。补丁挂在 `Verse.Widgets.ThingIcon(Rect, ThingDef, …)` 上，在绘制那一刻：

1. 若 `uiIcon` 为空或是 `BaseContent.BadTex`，按 `graphic.path`（退化用 `graphicData.texPath`，再退化为 `+ "_south"`）经 `ContentFinder<Texture2D>.Get(path, false)` 取真实贴图并写回 `def.uiIcon`；
2. 若 `uiIconMaterial` 名字以 `CutoutComplexUI` 开头，置空它，使图标改走普通路径 `DrawTextureWithTexCoords()` —— 与正常显示的图标（墙、口粮）完全同一条路径。

两条写入都是幂等的：字段健康时不做任何事。

### Обходной путь без мода / 不使用模组的临时规避

**RU.** Полностью надёжного обходного пути нет: проблемные здания имеют собственный UI-материал, и именно он вызывает потерю плитки. Частично помогает понижение нагрузки на текстуры (меньше одновременных построек/модов), но это не решение.

**ZH.** 没有完全可靠的免模组规避方式：出问题的建筑自带 UI 材质，正是该材质导致整块丢失。降低纹理压力（少装贴图类模组）可能减少闪烁，但不是解法。

## 8. Ограничение области / 影响范围说明

**RU.** Проблема наблюдается **не на всех устройствах**. На большинстве устройств иконки в меню строительства отображаются корректно. Наблюдаемая корреляция: у пострадавшего устройства GPU без поддержки BC-сжатия (программное декодирование текстур), из-за чего путь загрузки/подготовки текстур отличается от «обычного». Точную характеристику, включающую баг, мы подтвердить не можем — в отчёте фиксируется только факт: **проблема частичная, зависит от устройства**, и потому воспроизведение требует сопоставимого окружения.

**ZH.** 该问题**并非在所有设备上出现**，多数设备的建造菜单图标显示正常。观察到的相关点：出问题的设备其 GPU 不支持 BC 压缩（纹理解码走软件路径），使纹理加载/准备路径与常规设备不同。我们无法确认具体是哪一项设备特性触发，因此报告中只陈述事实：**这是一个只在部分设备出现的问题**，复现需要相近的环境。

## 9. Предложения разработчику порта / 给移植作者的修改建议

**RU.**
1. `BuildableDef.ResolveIcon()`: если `val.mainTexture == null`, брать текстуру по `graphic.path` (`ContentFinder<Texture2D>.Get`), иначе `uiIcon` остаётся пустым навсегда.
2. `ImGuiGuiBackend.DrawTextureWithMaterial()`: при недоступной `_MainTex` (или `passMaterial == null`) откатываться на `DrawTextureWithTexCoords()`, а не молча выходить.
3. Полезно добавить однократный лог, когда материал иконки отбрасывает плитку (`discard`/`DrawsNothing`), — сейчас диагностика полностью отсутствует.

**ZH.**
1. `BuildableDef.ResolveIcon()`：当 `val.mainTexture == null` 时，退回按 `graphic.path` 用 `ContentFinder<Texture2D>.Get` 取贴图，否则 `uiIcon` 会永久为空。
2. `ImGuiGuiBackend.DrawTextureWithMaterial()`：当 `_MainTex` 不可用（或 `passMaterial == null`）时回落到 `DrawTextureWithTexCoords()`，而不是静默返回。
3. 建议在图标材质导致整块 discard（或 `DrawsNothing`）时打一条一次性日志——目前这条链路完全没有诊断信息。
